# ADR-019: Рынок, кредиты, районы и рейтинг мэра без конца партии

Date: 2026-11-26. Status: accepted.

## Context

Issue #155 (эпик v1.4.5, «ADR до кода»). По `AGENTS.md` новый экономический паттерн фиксируется ADR до первого шага с кодом. В коде сегодня три опоры: `EffectiveUpkeepPolicy.Apply` делит содержание на `Divisor = 8`, `TaxPolicy` даёт лестницу 1/2/4 по трём `ZoneType`, `ZonalJobs` распределяет занятых по зонам кумулятивными долями; `QuestSystem` платит награду только в казну (`Treasury.Earn`, ADR-012). `Market`, `Loan`, `Credit`, `District` и рейтинга мэра в коде нет — все перечисленное ниже новые паттерны, а не переименование существующих.

Действие игрока: изменить рыночную цену и увидеть новую цену в HUD; взять кредит и увидеть, что процент списался даже при пустой казне; назначить району свою ставку и увидеть сбор с его клеток; выполнить веху и увидеть рост рейтинга в ленте — без экрана победы.

## Decision

- **`MarketPricePolicy` — чистая политика без Unity и состояния.** `Multiplier` по умолчанию `×1`, `Apply(basePrice)` при дефолте возвращает базу тождественно, иначе детерминированно округляет вниз к неотрицательному целому. Применяется ТОЛЬКО в точках цены (расчёт стоимости стройки, апгрейда, содержания, выручки) и в строках HUD. Не меняет ассеты `BuildingDefinition`/`RoadDefinition`, базовые ставки `TaxPolicy` и не подменяет собой счётчики. Порядок для содержания: `UpkeepPolicy` → `MarketPricePolicy.Apply` (дефолт ×1 — тождество) → `EffectiveUpkeepPolicy.Apply` (÷8 ровно один раз). Множитель не меняет `Divisor` и не отменяет деление.
- **`CreditLedger` — тело и процент в одной записи партии.** Тело (principal и остаток) и процент хранятся в `CreditLedger` как plain C# состояние; выдача тела идёт через `Treasury.Earn`, погашение и процент — через `Treasury.Charge`, а не `Treasury.TrySpend`. Процент считается целочисленно от остатка (`остаток × ставка / 100`, усечение к нулю, ставка и остаток неотрицательны) на границе тика. `Charge` проходит всегда и уводит баланс в минус: дефицит легален, `Treasury.IsInDeficit` — честный сигнал, а не ошибка и не поражение. `TrySpend` остаётся только для добровольных трат по правилу ADR-008 (стройка, дороги, апгрейд): при нехватке они по-прежнему отказывают.
- **Районы — override над `ZoneType`, а не новый тип зоны.** Клетка сохраняет базовый `ZoneType`; район задаёт переопределение ставки налога и рыночного множителя для своих клеток. Приоритет: override района > базовое значение `ZoneType`; нет района, неизвестный район или `ZoneType.None` → старое поведение (`TaxPolicy` по зоне, множитель ×1, сбор 0). Занятые по районам считаются по принципу `ZonalJobs`: неотрицательные значения, неизвестная зона/район пропускается, распределение занятых кумулятивными долями даёт в сумме ровно `employed`, нет мест — вся занятость в базовую корзину. Новый параллельный счётчик с другой арифметикой не вводится: существующий паттерн переиспользуется.
- **Рейтинг мэра — бесконечный производный счётчик, а не цель.** Значение выводится из вех (`QuestSystem.CompletedCount` и генератор ADR-012) и состояния казны/города детерминированной функцией без потолка и без порога «финиша». Рейтинг не является автономной сохранённой ценностью, не имеет экранов победы/поражения и не воскрешает `GoalSystem.Won/Lost` (доктрина GAME_DESIGN §19). Последствия рейтинга идут только через ленту (`CityEventLog`) и модификаторы уже существующих политик (налог, рынок, условия кредита); блокирующих режимов и финальных экранов нет.
- **Границы.** `GameSettings` остаётся профилем игрока (звук, оверлеи, автосейв, масштаб HUD) и НЕ используется для состояния партии: множитель, долг, районная карта и рейтинг живут в симуляции и, если сериализуются, в снапшоте по правилам ADR-014 (опциональные поля, fallback на v5, без перепроигрыша начислений). Новых глобальных синглтонов, ScriptableObject для состояния партии, reflection и ручного JSON нет.

## Consequences

- `EffectiveUpkeepPolicy.Divisor = 8`, лестница 1/2/4 и старые баланс-тесты не меняются: при дефолте ×1 и без районов все расчёты совпадают с текущими. Код экономики/власти пишется последующими шагами эпика, каждый ≤5 файлов и ≤250 строк.
- Тесты последующих шагов: тождество ×1 и порядок «множитель → ÷8», отказ `TrySpend` и легальный минус после `Charge`, приоритет override и fallback на `ZoneType`, распределение по районам с суммой ровно `employed`, монотонность рейтинга и отсутствие терминального состояния.
- Игрок видит изменения в HUD и ленте; экранов финала нет, старые слоты и профиль настроек сохраняют поведение (ADR-012, ADR-014, ADR-016).
