# ADR-013: Локализация ленты событий — ключ + аргументы вместо RU-литералов

Date: 2026-11-21. Status: accepted.

## Context

ADR-007 зафиксировал `CityEventLog` как append-only кольцо последних 50 событий: запись — RU-литерал (`Add(kind, message, tick)`), дедуп по `(kind, message)` в окне 10 тиков, форматирование — в view. Реестр локализации (`UI/Localization.cs`) уже хранит таблицы RU/EN по строковым ключам с плейсхолдерами `{0}`; RU/EN-меню переведены в v1.2.2 (tail #72).

Два конфликта при переходе ленты на локализацию:

- если переводить сообщение в момент `Add`, в ленте сохранится язык записи. Дедуп-ключ станет зависеть от языка: после смены языка то же событие пройдёт как новое и продублируется;
- `Presentation/AudioEventPolicy.Resolve` выбирает звук по тексту (`message.Contains("сгорел")`). RU-маркеры не работают в EN, а переход к ключам вовсе убирает из сообщения осмысленный текст.

По ADR-005 паттерн фиксируется до кода шагов #87/#88.

## Decision

- Формат хранения записи: `EventKind kind`, `string messageKey`, `object[] args`, `int tick` вместо RU-литерала. `messageKey` указывает в таблицу локализации, `args` — значения для плейсхолдеров.
- Готовую строку формирует только view (`EventLogView`) в момент отрисовки: реестр локализации по `messageKey` и текущему языку + подстановка `args`. Домен не знает язык.
- Дедуп по `(kind, messageKey, args)` в существующем окне 10 тиков. Идентичность записи не зависит от языка.
- Смена языка перерисовывает уже существующие записи из `key + args`; `Add` не вызывается, новые записи не появляются — дублирования нет.
- Звук выбирается по типу события, хранимому в записи (отдельный подтип/ключ события), а не по `message.Contains(...)`. Маркеры `BurnedMarker`/`ExtinguishedMarker` удаляются; RU и EN дают один и тот же звук. Начало пожара, сгоревший дом и потушенный пожар — разные типы/ключи, а не варианты текста.
- Лента по-прежнему не сериализуется (ADR-007): append-only кольцо на 50 записей. RU-вывод остаётся байт-в-байт прежним — новые ключи дают те же строки.

## Consequences

- Вызовы `Add` переходят на `(kind, messageKey, args, tick)`; для каждого сообщения ленты заводится ключ в `Localization` с прежним RU-текстом.
- Сигнатура дедупа меняется, но поведение внутри одного языка сохраняется. Тесты: независимость дедупа от языка, отсутствие дублей при смене языка, выбор звука по типу, байт-идентичность RU-вывода.
- `AudioEventPolicy` больше не парсит локализованный текст — звук стабилен при смене языка и при любых `args`. Ключ опроса звука (`KeyOf`/`NewEventsStart`) строится из `(tick, kind, messageKey, args)`, а не из готовой локализованной строки: иначе смена языка меняет `lastKey` и последнее событие проигрывается повторно. `AudioEventView.PollNow` не содержит иного зависящего от языка кода, кроме вызовов `KeyOf` и `Resolve`; поэтому проверки стабильности звука и ключа при RU→EN в `AudioEventPolicyTests` полностью покрывают требование отсутствия дублей звука, отдельный Unity-тест вью не требуется.
