# ADR-022: Сейв v7 — опциональные поля дорог, кредитов, рыночного множителя, районов, рейтинга и вех v2

Date: 2026-11-26. Status: accepted.

## Context

Issue #158 (эпик v1.4.5, «ADR до кода»). Текущий контракт: `CitySnapshot.Version = 6` на записи, `SaveSystem.CurrentVersion = SaveV6Snapshot.Version`, чтение версий 1–6 через `SaveSlotStorage.Validate`, нормализация полей v6 в `SaveV6Snapshot.Normalize` без исключений, экспорт/импорт `SlotTransfer` через тот же JSON `JsonUtility` и ту же валидацию (ADR-014, ADR-016).

Новые системы требуют в слоте тип и уровень дороги, долг и процент по кредиту, множитель рынка, ставки по районам, рейтинг мэра и счётчик вех v2. Без этих полей после загрузки и переноса слота теряются улучшения дорог, кредитная история, районная политика и прогресс вех; старые слоты v1–v6 должны продолжать работать как раньше.

Действие игрока: построить дорогу нового типа/уровня, взять кредит, изменить ставку района → сохранить и загрузить слот или перенести его экспортом/импортом → состояние сохраняется, а старый слот v6 по-прежнему грузится без этих полей.

По `AGENTS.md` новый паттерн персистентности внутри эпика фиксируется ADR до первого шага с кодом.

## Decision

- **Version bump:** `CitySnapshot.Version` становится `7` только на записи; `SaveSystem.CurrentVersion` берётся из нового `SaveV7Snapshot.Version = 7`. Чтение принимает версии 1–7; версия > 7 (как и 0/отрицательная) — ошибка валидации слота (`SaveSlotStorage.Validate` → `false`), не тихий даунгрейд. Старые файлы на диске при загрузке не переписываются; поля v7 появляются только после явного сохранения или автосейва.
- **Опциональные поля v7** (добавляются в `CitySnapshot`; запись, нормализация и чтение — в отдельном `SaveV7Snapshot.cs` по образцу `SaveV6Snapshot.cs`), все без обязательного присутствия в JSON:
  - `RoadEntry.Type` / `RoadEntry.Level` — тип и уровень дороги. Fallback v6: `Type = 0` (обычная асфальтированная дорога), `Level = 1`; `Level = 0` тоже трактуется как 1 (как `BuildingEntry.Level` в v5). Неизвестный тип или уровень вне 1..3 → дефолты; сама дорога при этом не удаляется.
  - `Debt` и `DebtInterestPercent` — долг и процент кредита. Fallback v6: долг `0`, процент `0`. Отрицательный/неконечный долг или процент вне 0..100 → дефолты; долг не превращается в минусовый баланс и не перепроигрывает начисления за прошедшие тики.
  - `MarketMultiplier` — множитель рынка. Fallback v6: `1.0` (нейтральный). `NaN`, бесконечность и значения ≤ 0 → `1.0`.
  - `DistrictTaxRates` — список ставок по районам (идентификатор района + ставка 1..3). Fallback v6: пустой список, действуют только ставки v5 `TaxRates` / `TaxLevel`; новые районы не создаются. Записи с пустым id или ставкой вне 1..3 отбрасываются, дубли по идентификатору дедуплицируются (остаётся последняя), длина списка ограничена размером сетки текущему размеру сетки из GridVisualizer (100×100 в v1.4.5).
  - `MayorRating` — рейтинг мэра, 0..100. Fallback v6: `0` («не рассчитан», без бонусов и штрафов); значение вне диапазона → `0`.
  - `MilestoneCounterV2` — счётчик вех v2. Fallback v6: `0`; отрицательное значение → `0`. Применение счётчика не перепроигрывает награды и не порождает повторные события в ленте; цепочка v5 `QuestActive` / `QuestCompleted` сохраняется без изменений.
- **Fallback:** отсутствующее, `null` или пустое поле v7 читается как указанный дефолт; ни одно новое поле не является обязательным для успешной загрузки. Все поля и правила v1–v6 (`TaxLevel`, `TaxRates`, `GoalStage`, `ManualBuildings`, квесты, `BuildingEntry.Level`, очереди мусора, кражи, серия комфорта, прогресс стройки) остаются без переименований и изменений.
- **Валидация в `SaveSlotStorage`:** после успешного `Validate` вызываются `SaveV6Snapshot.Normalize` и `SaveV7Snapshot.Normalize`; нормализация не бросает исключения — битые и дублирующиеся значения v7 получают дефолты или отбрасываются, но не отклоняют слот. Действующие правила отклонения некорректных слотов v1–v5 (`TickCount < 0`, `TaxLevel` вне 0..3, невалидные `TaxRates`, `GoalStage`, зоны, здания, домохозяйства, дороги, `BuildingEntry.Level`) сохраняются полностью. `JsonUtility.FromJson` по-прежнему обёрнут в try/catch: нечитаемый JSON даёт `null`, а не падение загрузки.
- **Экспорт/импорт `SlotTransfer`:** тот же JSON `CitySnapshot` через `JsonUtility`, `Export` проверяет `SaveSlotStorage.Validate` перед записью, `Import` проходит ту же валидацию и обе нормализации, что и обычная загрузка. Версия > 7 отклоняется и при импорте, и при экспорте. Запрещены reflection, async/await, ручная сериализация JSON, новый сериализатор и облачные сейвы. Пожары и агенты не сериализуются (ADR-009/011/014).
- **Поправка к ADR-014/016:** настоящий ADR расширяет их правила на v7 в части версии, fallback, валидации и экспорта/импорта; сами файлы `DECISIONS/ADR-014-save-v6.md` и `DECISIONS/ADR-016-v14-scope.md` не изменяются.
- **GameSettings — профиль, не состояние партии:** настройки игрока (звук, оверлеи, лимиты, интервал автосейва) хранятся в `GameSettings`/`PlayerPrefs`, в `CitySnapshot` не пишутся и через `SlotTransfer` не переносятся. Все поля v7 — состояние города, а не пользовательские настройки.

## Consequences

- Следующий шаг — только код по ≤5 файлов: `CitySnapshot.cs`, `SaveV7Snapshot.cs`, `SaveSystem.cs`, `SaveSlotStorage.cs`, `SlotTransfer.cs`; сцена, Unity и `GameSettings` не трогаются.
- Тесты последующих шагов: round-trip v1–v7; загрузка v6 без полей v7; отказ версии > 7; null/битые/дубли v7-полей без исключений; экспорт/импорт с теми же правилами; отсутствие двойной награды за вехи; профиль настроек не попадает в слот.
- Игрок видит честное сохранение новых дорог, кредитов, районных ставок, рейтинга и вех после перезагрузки и переноса слота; старые слоты v1–v6 ведут себя как раньше, а их версия меняется на 7 только после явного сохранения.
- Статическая проверка шага — `python Tools/ValidateRepo.py`: 0 ERROR. Пуш, мерж и запуск Unity этим ADR не предполагаются.
