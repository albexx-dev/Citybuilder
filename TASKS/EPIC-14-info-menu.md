# EPIC-14: UI v2 — информационное меню

Issue: #14 · Ярлык: ux · Зависимости: EPIC-13 (кнопка «Статистика» уже зарезервирована в панели) · UI остаётся на IMGUI

## Проблема

Левая колонка HUD — 12+ строк статистики (потребности, цель, связность, энергия, вода, мусор, пожарные/полиция, налог, «Дальше», подсказка, статус роста) поверх игрового поля. Экран загромождён, строки конфликтуют на низких окнах (задача v1.1 чинила клампами — костыль поверх плохого макета).

## Что увидит игрок

Чистый игровой экран: сверху только **деньги, население, день/час**; всё остальное — по кнопке «Статистика» (нижняя панель) или хоткею Tab открывается меню со секциями:
- **Город**: потребности (9 показателей), население (семьи/жители), занятость;
- **Цель**: текущая веха (N/50/100/200), награда;
- **Сети**: связность, энергия, вода, мусор — с числами «N/M (Z%)»;
- **Службы**: пожарные, полиция, больницы, досуг;
- **Бюджет**: налог (кнопка уровней + фактический сбор «+N $/ч»), расход «−N $/ч» (EPIC-04), баланс;
- **Развитие**: «Дальше: …», привлекательность (EPIC-05), пробки (EPIC-15 — секция появится).
Статус роста («следующий дом через 5 ч») остаётся виден на экране — он игровой, не справочный.

## Архитектурный план

- `Scripts/UI/InfoMenuView.cs` (IMGUI): окно ~половина ширины экрана справа, рисуется ТОЛЬКО открытым (OnGUI-перф: закрытое меню ничего не рисует и не аллоцирует); секции — вертикальный скролл при малой высоте.
- Перенос строк из `NeedsView`, `GoalView`, `ConnectivityView`, `PowerView`/`WaterView`/`WasteView`, `FireCoverageView`, `TaxPolicyView`, `ProgressionView`: **сами view-классы не удаляются до EPIC-16** — их данные продолжают жить у контроллеров, строки рендерит `InfoMenuView` из тех же снимков. После переноса старые позиции в `HudLayout` гасятся.
- Верхний HUD: `$1500`, `Pop`, `Day, Hour` — три строки с подложками, клампы сохраняются.
- `GrowthStatusView` и `StartHintView` (→ EPIC-18) остаются на экране.
- Хоткей Tab + кнопка панели; `UiClickGuard` на прямоугольник меню.

Что НЕ делаем: переработка самих данных/контроллеров, вкладки-переключатели (один скролл), стили кроме подложек.

## Шаги

1. **menu-shell** — `InfoMenuView` + Tab + кнопка; пока рисует те же строки-дубликаты (старый HUD ещё жив — сравнение до/после на одном кадре).
2. **move-rows** — перенос всех строк по секциям, гашение старых позиций в левом HUD; остаются только 3 верхние + статус/подсказка.
3. **low-window-pass** — скролл меню на 600 px высоты, матрица скриншотов.

## План тестов

- Тесты существующих политик/вью-данных не переписываются (данные те же) — если тест рендера ломается, он обновляется на новый источник строк честно.
- Rect-тест: меню не пересекается с нижней панелью (из `HudLayout`) во всём диапазоне окон EPIC-13.

## Unity-приёмка (E2E)

Игровой экран чистый (3 строки сверху + статус), все 6 секций меню показывают живые числа, налог переключается из меню, Tab открывает/закрывает, клик по меню не проваливается в сетку. Скриншоты: закрытое меню 1080p, открытое 1080p, открытое 1280x600. Консоль чистая.

## Критерий закрытия эпика

Вся статистика доступна из меню, игровой экран чистый, перфа-деградации нет (закрытое меню не рисует), тесты зелёные.

## Запрещено / риски

- Не удалять view-классы в этом эпике — их судьба решается в EPIC-16/21 (часть станет источниками данных).
- Риск «двойного экрана» чисел (HUD + меню) — шаг 2 обязан погасить старые позиции, ревьюер сверяет по скриншоту.
- Perf: строки собираются в кеш при открытии/тике, не в каждом OnGUI.
