# EPIC-17: Стадии роста зданий (визуал)

Issue: #17 · Ярлык: ux · Зависимости: нет; виды домов обогащаются моделями EPIC-20 · Только view-слой, домен не трогается

## Проблема

Дом появляется мгновенно готовым — город не ощущается живым. Все дома выглядят одинаково (один куб-примитив с крышей из задачи 022), улицы из клонов.

## Что увидит игрок

Новый дом сначала — «стройка» (заготовка: масштаб ~60%, серый материал, 2-3 тика), затем вырастает в готовый. Дома одного типа слегка различаются: 2-3 варианта внешнего вида (высота/крыша/оттенок по образцу задачи 022), выбор детерминированный.

## Архитектурный план

- `Scripts/Presentation/GrowthStageView.cs`: компонент/логика при создании здания через `BuildingViewFactory`:
  - фаза стройки: масштаб 0.6, материал «каркас» (серый, без крыши), длительность `constructionTicks = 3` (константа view-слоя);
  - переход в готовую по истечении тиков (подписка на `TickCompleted` — сцена уже даёт часы);
  - рост масштаба 0.6→1.0 плавно за последний тик (интерполяция в Update — визуальная, без домена).
- Варианты: `BuildingDefinition` получает `variantCount` (int, default 1) + правило выбора `variantIndex = (int)(EntityId.Value % variantCount)` — детерминировано, без рандома; параметры варианта (высота стен 1/1.5/2 из задачи 022, оттенок крыши) — внутри `BuildingViewFactory`.
- Сейв/лоад: варианты и фазы НЕ сериализуются; при загрузке все здания готовые (существующее поведение восстановления по `HasHome`/manual не меняется) — зафиксировать как допустимое упрощение.
- Снос в фазе стройки: работает как обычный снос (клетка освобождается, деньги не возвращаются — существующие правила).

Что НЕ делаем: прогресс-бары стройки в домене, изменение времени роста/платежа (рост по тикам и плата из задач 034/101 не трогаются), новые модели (EPIC-20).

## Шаги

1. **construction-phase** — фаза стройки 3 тика + переход; E2E визуально + сейв/лоад.
2. **variants** — `variantCount` в Definition + детерминированный выбор; ассеты: дома variantCount=3; E2E улица из разных домов.
3. **polish** — интерполяция масштаба, согласование с зоной/сносом; скриншот-матрица.

## План тестов

- `variantIndex` детерминирован: одинаковый EntityId → одинаковый вариант (чистая функция).
- Фаза стройки не влияет на домен: население/казна/нужды считаются так же, как без фазы (тест: growth-метрики идентичны с включённой и выключенной фазой — фейковая фабрика видов).
- Снос в стройке: клетка освобождена, здание удалено, исключений нет.

## Unity-приёмка (E2E)

Включить рост → дом появляется «каркасом» и строится на глазах за 3 тика; 5 домов на улице — минимум 2 разных вида; сейв/лоад → все готовы, ничего не сломано; снос строящегося — чистый. Скриншоты: каркас, готовый, улица с вариантами. Консоль чистая.

## Критерий закрытия эпика

Стройка видна, варианты детерминированы, домен и сейв не затронуты, тесты зелёные.

## Запрещено / риски

- Никакого рандома в выборе варианта — только EntityId (иначе сейв/лоад «перекрашивает» город).
- Риск: фаза стройки «съедает» ощущение скорости на x4 — длительность 3 тика проверить на глаз на обеих скоростях; если плохо — константа правится одним числом.
