# EPIC-64: Сейв v5 — уровни зданий, квесты, состояние служб

Issue: #64 · Ярлык: architecture · Зависимости: #49 (налоги по зонам), #51 (апгрейды), #59 (уровни), #48 (квесты) — поля от них

## Проблема

Новые доменные состояния v1.2 не переживают сейв/лоад: уровень дома, уровень станций, 3 налоговые ставки, прогресс квестов. Снапшот v4 их не хранит.

## Что увидит игрок

Всё построенное/улучшенное/заработанное живёт через сейв/лоад/автосейв — как в v1.1, плюс новые поля.

## Архитектурный план

- `CitySnapshot` v5 (обратно совместимое расширение): `HouseLevels[]` (по координатам дома, как HouseholdBinder), `StationLevels[]`, `TaxRates` (3 int), `QuestState` (активные id + прогресс + выполненные id).
- Чтение v4 → дефолты (уровень 1, одна ставка ×3, квесты заново) — паттерн v4←v1 (задача 081/090).
- Валидация `SaveSlotStorage`: новые поля проверяются (уровни 1..3, ставки 1..3), битые — отбраковка слота (не удаление).
- Автосейв и 3 слота (v1.1) продолжают работать без изменений.

## Шаги

1. **snapshot-v5** — поля + читатели v4-совместимость + валидация + тесты.
2. **apply-load** — восстановление уровней/ставок/квестов в контроллеры + тесты round-trip.
3. **integration** — автосейв/слоты прогон с новыми полями.

## План тестов

- Round-trip v5 всех полей; v4-файл → читается с дефолтами; битые значения → слот отбракован.
- Уровень дома по координатам привязан как домохозяйства (паттерн задачи 096).

## Unity-приёмка (E2E)

Улучшить станцию + вырастить дом до уровня 2 + взять квест → сейв → новая → загрузка → всё на месте (баланс без повторной награды). Скриншот. Консоль чистая.

## Критерий закрытия эпика

v5 пишет/читает всё новое; старые сейвы живы; валидация строже, но не ломает совместимость.

## Запрещено и риски

- Не менять существующие поля v4 (только добавление) — контракт совместимости.
- Риск: квест-прогресс рассинхронится с генератором после лоада — тест «выполненные не повторяются».
