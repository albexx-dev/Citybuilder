## Что увидит игрок

Ничего — поведение идентично, это рефакторинг без изменения семантики. Критерий честности: дифф каждого шага только выносит код в новый файл + вызывает его.

## Архитектурный план (что именно выносится)

1. **SettlementGrowthController → GrowthEligibilityPolicy** (Population, plain C#): проверка «может ли вырасти следующий дом» — режим роста, зоны, казна, потолок. Контроллер остаётся тонким адаптером: тик → policy → действие. Цель: контроллер ≤ 150.
2. **GridMeshBuilder → ZoneMeshBuilder** (Presentation): построение мешей ЗОН (инсет-квадраты из задачи 021) отдельно от меша линий сетки/ховера. Оба файла ≤ 150.
3. **RoadPlacementController → RoadPlacementInput** (World): чтение ввода (drag, валидация клеток) отдельно от применения к `RoadNetworkStore`. Контроллер ≤ 150.
4. **Удалить** пустую `Construction/Editor/` (папка + .meta).

Правило сплитов: имя нового файла — по сущности, не по слову «Helper»; 1 файл = 1 класс; публичный API контроллеров не меняется (сцена не перенастраивается, кроме случая 4).

## Шаги

1. **split-growth-policy** — шаг 1 + тесты переносятся/добавляются на policy.
2. **split-zone-mesh** — шаг 2 (визуал: E2E-скриншот сетки и зон до/после — попиксельно одинаково).
3. **split-road-input** — шаг 3 + E2E дорог (стройка/снос/продолжение из задачи 015).
4. **cleanup-editor-folder** — шаг 4 + `git rm`.

## План тестов

- На каждый вынос: существующие тесты модуля зелёные без правок (значит API не сломан) — если тест надо править, сплит пошёл не туда.
- `GrowthEligibilityPolicy`: матрица (режим off/нет зон/нет денег/потолок/ок) — 5 кейсов.
- Валидатор после каждого шага: warning по этим файлам исчезает.
