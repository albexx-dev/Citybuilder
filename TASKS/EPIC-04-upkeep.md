# EPIC-04: Содержание зданий (upkeep)

Issue: #4 · Ярлык: mechanics · Зависимости: EPIC-02 (службы на карте); независимо от EPIC-03

## Проблема

Экономика односторонняя: город только зарабатывает (налоги за работающих) и платит единожды за стройку. Станции и службы после установки «бесплатны навсегда» — нет давления на бюджет, поздняя игра не имеет вызова, дефицит казны ничего не значит.

## Что увидит игрок

Каждое здание стоит денег в час: строка «Расход: N $/ч» рядом с налогом. Если расход превысил доход, казна тает; при балансе ≤ 0 рост города останавливается со статусом «казна пуста», а лента (EPIC-09) получает событие. Восстановление — поднять налог или снести лишнюю станцию.

## Архитектурный план

- `BuildingDefinition`: новое поле `upkeepPerHour` (int, ≥ 0; SerializedField с Tooltip, OnValidate-клампы по образцу задачи 071). Значения по типам (стартовые, подтвердит EPIC-06):
  - дом 0, магазин 1, фабрика 2;
  - электростанция 8, водонапорная 6, мусорный полигон 5;
  - пожарная 6, полиция 6, больница 10, парк 2.
- `UpkeepPolicy.cs` (Core, plain C#): `UpkeepPerHour(IEnumerable<BuildingDefinition> placed)` — сумма по размещённым зданиям; без состояния.
- `EconomyTicker`: за тик `net = TaxSystem.Collect − UpkeepPolicy.UpkeepPerHour`; балансовая запись в `Treasury` через существующий `BalanceChanged`.
- Политика отрицательного баланса: `Treasury` разрешает уход в минус от содержания (Spend за стройку по-прежнему отказывает при нехватке — правило задачи 008 не трогаем); новый флаг `IsInDeficit` доступен запросом.
- Рост: `SupplyGrowthController`-образец — новый множитель в `GrowthPace` (худший из: пробки, снабжение, дефицит казны ×1/×2/×3 → при дефиците рост стоит, т.е. множитель «стоп» = отдельный bool-гейт до множителей).
- HUD: строка «Расход: N $/ч» из того же паттерна `TreasuryView`.
- Сейв: формат v4 не меняется — содержание вычисляется из определений, ничего не храним.

Что НЕ делаем: кредиты/долги с процентами, отключение служб при дефиците, попап-предупреждения (в ленту — EPIC-09).

## Шаги

1. **upkeep-domain** — поле в Definition + `UpkeepPolicy` + сумма в `EconomyTicker` + `IsInDeficit` в `Treasury`; тесты на сумму и границу нуля.
2. **deficit-growth** — гейт остановки роста при дефиците в `GrowthPace`; тесты: дефицит → стоп, восстановление → рост.
3. **hud-deficit** — строка расхода, индикация дефицита (цвет строки через `HudText`-подложку), значения upkeep в 10 ассетах.

## План тестов

- Сумма содержания: 2 станции + 3 дома → ожидаемое N $/ч.
- Дефицит: баланс 5, расход 6/ч → через тик баланс −1, рост остановлен; +налог → баланс ≥ 0, рост продолжился.
- Spend при балансе 0 и дефиците — отказ на стройку (старое правило не сломано).
- NaN/отрицательное upkeep в ассете → OnValidate клампит в ≥ 0.

## Unity-приёмка (E2E)

Новый город 1500$: построить городок + 2 станции → строка расхода видна; слить казну содержанием → статус «казна пуста», дома не растут; поднять налог → рост ожил. Скриншот HUD с расходом. Консоль чистая.

## Критерий закрытия эпика

Содержание списывается за тик, дефицит останавливает рост с видимой причиной, восстановление работает, формат сейва не менялся, тесты зелёные.

## Запрещено / риски

- Не ломать правило «Spend при нехватке — отказ» (контракт задачи 008 и тестов казны).
- Риск: содержание убило раннюю игру (станция обязательна по задаче 093 — источник энергии нужен сразу). Стартовые значения upkeep заданы мягкими; правки цифр — только в EPIC-06.
