# EPIC-62: Оптимизация агентов — пул, LOD, профайлер-проход

Issue: #62 · Ярлык: architecture · Зависимости: #44 (машины), #46 (пешеходы), #54 (модели зданий) · возможно малый ADR-013 (единый AgentManager)

## Проблема

Три вида агентов (машины/пешеходы/мусоровозы) из независимых менеджеров рискуют: дублировать пулы, аллокации в Update, перерисовывать за пределами камеры. На слабом железе v1.2 может просесть именно из-за агентов.

## Что увидит игрок

Ничего нового — гарантия: 80 зданий + 40 машин + 30 пешеходов + декор = стабильные FPS на средней машине. Плюс настройка качества.

## Архитектурный план (ADR-013 — малый, при необходимости)

- Единый `AgentManager` (plain C#): реестр всех агентов, один пул, лимиты по типу, приоритет видов по близости к камере (квантованное обновление дальних).
- LOD-правила: агент вне камеры/дальше X — вид скрыт (агент жив), ближние — полный вид; обновление позиций видов батчем раз в кадр.
- Правила кода: без аллокаций в Update (списки переиспользуются), без LINQ, тик ≤5 мс суммарно с симуляцией.
- Настройка качества (#69): лимиты агентов/декора/тени.

## Шаги

1. **manager-unify** — единый менеджер + миграция #44/#46/#52 на него + тесты.
2. **lod-views** — приоритеты/скрытие видов + тесты.
3. **profiler-pass** — замеры до/после, документ цифр в issue, настройки качества.

## План тестов

- Пул без утечек (длинный прогон 500 тиков в EditMode-заглушке).
- Приоритет видов: детерминированный порядок по расстоянию.
- Тик ≤5 мс: измерение в тесте-заглушке (100 агентов, путь по сетке).

## Unity-приёмка (E2E)

Профайлер в билде: кадр ≤8 мс, тик ≤5 мс при целевой нагрузке; FPS-скриншот. Переключение качества на лету.

## Критерий закрытия эпика

Целевые лимиты достигнуты и задокументированы; менеджер один; настройки работают.

## Запрещено и риски

- Jobs/Burst/DOTS — запрещены (ADR-001 аккуратно: их появление — новый ADR).
- Риск: преждевременная оптимизация ДО готовности агентов — эпик выполняется после #44/#46.
