# EPIC-11: Сейвы v2 — три слота + автосейв

Issue: #11 · Ярлык: architecture · ADR: `DECISIONS/ADR-008-saves-v2.md` · Зависимости: нет; UI выбора слота встраивается в меню EPIC-16

## Проблема

Сохранение только в `slot0.json` (F5), загрузка F9. Один неосторожный сейв — потерян город. Автосейва нет. ADR-002 отложил персистентность «за пределы слота» — время снять часть отложенного.

## Что увидит игрок

Меню сохранения/загрузки с тремя слотами (имя + игровое время + дата), автосейв каждые 24 игровых часа в отдельный слот «Автосейв». F5/F9 работают как раньше (быстрый слот 0). Новый город не затирает автосейв.

## Архитектурный план

- `SaveSlotStorage.cs` — параметр слота:
  - `Save(int slot, CitySnapshot snapshot)`, `Load(int slot)`, `Validate(int slot)`; файлы `slot0.json`, `slot1.json`, `slot2.json`, `autosave.json`;
  - `slots.json` — индекс `{ "slots": [ {"file","name","savedAtTick","savedAtReal"} ] }`, перезаписывается при каждом сохранении; отсутствующий индекс = пустые слоты;
  - существующая `Validate` (отбраковка вне-карты координат, налога, ступени — задача v1.1) работает для любого слота.
- `SaveController`/`LoadController`: методы получают `int slot` (перегрузки: старые `SaveNow()/LoadNow()` = слот 0 — F5/F9 и сцена не меняются).
- `AutosaveController.cs` (Persistence, тонкий MonoBehaviour): подписка `TickCompleted`, счётчик — каждые 24 тика собирает снапшот и пишет `autosave.json`; в паузе не тикает (подписка живёт на тиках — автоматически).
- UI: `SaveMenuView`/`LoadMenuView` (IMGUI) — 3 слота + автосейв (только чтение), открываются из меню (EPIC-16) и кнопкой; имя слота редактируемое.
- Формат снапшота v4 НЕ меняется.

Что НЕ делаем: облако, экспорт/импорт файлов, ротация автосейвов, слоты > 3.

## Шаги

1. **storage-slots** — параметр слота в `SaveSlotStorage` + `slots.json` + перегрузки контроллеров; тесты.
2. **autosave** — `AutosaveController` + тесты времени (fake tick-источник: 23 тика — нет, 24 — есть, пауза — нет).
3. **slots-ui** — `SaveMenuView`/`LoadMenuView` + точка входа из главного меню; E2E всех слотов.

## План тестов

- Round-trip каждого из 3 слотов + autosave: снапшот = файлу один в один (матрица из задачи 044).
- Обратная совместимость: старый `slot0.json` (без имени в индексе) читается, индекс дополняется.
- Битый `slot2.json` → Validate отказывает, остальные слоты живы (изоляция слотов).
- Автосейв: 23/24/25 тиков; пауза останавливает счёт; «Новая» не трогает autosave.json.
- Индекс `slots.json` битый (мусор) → все слоты считаются пустыми, сейвы на диске не удаляются.

## Unity-приёмка (E2E)

Сохранить в слот 1 и 2 с разными именами; загрузить каждый; автосейв через x4 (24 часа) появляется сам; загрузка из автосейва точна (баланс, тик, ступень, домохозяйства). Скриншот меню слотов. Консоль чистая.

## Критерий закрытия эпика

3 слота + автосейв работают, индекс жив, старый slot0 читается, F5/F9 не изменились, тесты зелёные.

## Запрещено / риски

- Не менять `CitySnapshot` (v4) — только хранилище и контроллеры.
- Риск одновременной записи (автосейв + ручной сейв в один кадр): запись на главном потоке в OnGUI/тик — гонки нет, но зафиксировать порядок в тесте (автосейв пропускается, если в этом тике был ручной сейв).
- Файлы слотов лежат рядом с slot0 (persistent-путь существующего хранилища) — путь не менять.
