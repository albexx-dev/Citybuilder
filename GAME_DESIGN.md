# Citybuilder Game Design

## 1. Game fantasy

Игрок — мэр и планировщик живого города. Город растёт как система: решения в одном месте отзываются в другом.

## 2. What the player does

Планирует город, строит дороги, размечает районы, ставит здания, управляет бюджетом, ресурсами, инфраструктурой и транспортом, следит за нуждами жителей.

## 3. City development loop

Построить → заселить → дать работу → получить налоги → улучшить сети → повысить привлекательность → привлечь новых жителей → расширить город.

Связи: дороги → доступность → время поездок → доступность работы → доход → потребление → экономика; коммуналка → качество жизни → привлекательность.

## 4. Buildings

Типы: жилые, коммерческие, промышленные, инфраструктурные, общественные. V1: только 1 дом 2x2 без заселения. Параметры типа: размер, стоимость, рабочие места, потребление/производство (после V1).

## 5. Roads

Клеточные, соединяются в сегменты, дают доступность зданий. V1: дорог нет. Этап 4.

## 6. Districts

Жилые / коммерческие / промышленные зоны. После среза (Этап 5).

## 7. Resources

Electricity, Water, Food, Materials, Fuel, Waste. Вводить по одному, не все сразу. V1: нет.

## 8. Economy

Бюджет, доходы/расходы, стоимость строительства, налоги. V1: только казна — начальный баланс, списание за стройку, запрет при нехватке, UI баланса, понятный результат транзакции.

## 9. Population

Граждане и домохозяйства: жильё, работа, доход, образование, потребности, миграция. Начать с домохозяйств, не с детальной симуляции каждого. V1: жителей нет.

## 10. Jobs

Рабочие места в зданиях, доступность зависит от транспорта. После Этапа 5.

## 11. Needs

Жильё, доход, еда, здоровье, образование, безопасность, досуг. Влияют на счастье и миграцию. После V1.

## 12. Infrastructure

Электричество, вода, канализация, мусор, пожарные, полиция, медицина, образование. По одной службе за раз. После V1.

## 13. Transport

Маршруты, поездки, нагрузка, общественный транспорт, пробки. После сетки, дорог, домов и работы (Этап 8).

## 14. Events and problems

Пробки, безработица, нехватка воды/света, пожары, жалобы. После базовой симуляции.

## 15. Progression

Открытие новых зданий и политик за рост населения и бюджет. Баланс позже.

## 16. Difficulty

Старт с запасом денег, мягкие штрафы. Жёсткая экономика после среза.

## 17. First playable prototype

1. Камера сверху.
2. Сетка 50x50.
3. Один дом 2x2 (куб-примитив).
4. Предпросмотр: зелёный — можно, красный — нельзя.
5. Проверки границ и занятости.
6. Установка занимает клетки, удаление освобождает.
7. Начальный бюджет, стоимость стройки, UI баланса, отмена по Escape.

## 18. v1.1 scope (supersedes the frozen minimal release)

Первый минимальный релиз состоялся в задаче 047; заморозка ADR-004 снята post-release amendment. Актуальные рамки — `DECISIONS/ADR-005-v1.1-scope.md` и `AGENTS.md` → Scope lock.

В v1.1 входит реализованное в задачах 001–104 и эпиках v1.1: сетка 50×50, зоны, рост по тикам, население, налоговая политика, содержание зданий, привлекательность города, энергия / вода / мусор, пожарные / полиция / больницы / парки по радиусу, связность дорог и пробки, ступени цели 50/100/200, сохранение (с поддержкой дефицита казны), стартовая подсказка, статус роста, нижняя панель действий и инфоменю.

Экраны победы/поражения удалены задачей 049. Без нового ADR по-прежнему запрещены: транспорт с машинами, облачные сейвы, Jobs/Burst, DI-контейнеры, `async/await`, новые сторонние пакеты. Многоуровневость по-прежнему запрещена для зданий; для дорог и мостов допущена по ADR-018.

## 19. No ending (песочница без финала)

Решение владельца от 08.11.2026: партия **не имеет конца**. Экранов победы и поражения нет и не будет; `GoalSystem.Won/Lost` признаётся мёртвым кодом и удаляется в v1.1.

Цель со ступенями 50/100/200 остаётся вехами роста с наградами: после последней ступени город развивается свободно, без «конца игры». Долгосрочная мотивация — рост, службы и баланс, а не финальный экран.

## 20. Balance (v1.2)

Сведённая таблица баланса v1.2 (эпик #53): содержание служб и промышленности реальное, налоговая лестница 1/2/4 (низкий/обычный/высокий), дефолт обычный 2/2/2 во всех зонах. Источник каждой цифры указан в строке: файл с номером строки для логики и значений по умолчанию, имя ассета для данных типа, `Prototype.unity` для значений в сцене.

**С v1.4.0:** колонка Upkeep — базовое значение ассета; фактическое списание = база ÷ 8 (`Scripts/Economy/EffectiveUpkeepPolicy.cs`), при базе < 8 списание 0. HUD показывает уже эффективную сумму.

### v1.4.5 «Большой город» (issue #171, ADR-017…022)

Правила ниже зафиксированы ADR до кода; новые числа баланса (интервал въезда, налоги, содержание, темп роста) пересматриваются по фактическим замерам и здесь не выдумываются.

- **Карта и население (ADR-017):** 100×100 при клетке 1×1 м, размеры и `CellSize` читаются только из `GridVisualizer`; потолок застройки конфигурируемый под 400 домов при 4 жителях на дом (1000+ жителей). Лимиты агентов 12/30 не меняются без замеров Profiler. `Width`/`Height`/`CellSize` в снимок не попадают — старые слоты v1–v6 остаются загружаемыми.
- **Дороги и мосты (ADR-018):** four road types — `asphalt`/`brick` (level 1) и `wood`/`stone` (level 2). Ключ клетки `RoadCellKey(X, Y, Level)`; съезды 1↔2 на концах моста, маршрут не «проваливается» на нижнюю дорогу без съезда; мост без съезда — тупик. Под мостом нижняя дорога сохраняется и доступна маршрутам level 1; снос моста восстанавливает нижнюю дорогу без пересчёта.
- **Рынок (ADR-019):** `MarketPricePolicy` — множитель ×1 по умолчанию, при дефолте `Apply(basePrice)` тождественно возвращает базу; иначе округляет вниз к неотрицательному целому. Применяется только в точках цены и в строках HUD. Для содержания порядок: `UpkeepPolicy` → множитель → `EffectiveUpkeepPolicy` (÷8 ровно один раз). Лестница 1/2/4, базовые ассеты и `Divisor = 8` не меняются.
- **Кредиты (ADR-019):** `CreditLedger` — plain C# состояние партии; тело выдаётся через `Treasury.Earn`, погашение и процент идут через `Treasury.Charge` (целочисленно `остаток × ставка / 100`, усечение к нулю). Процент списывается на границе тика и уводит баланс в минус — дефицит легален (`Treasury.IsInDeficit`), не поражение. `TrySpend` остаётся только для добровольных трат (стройка, дороги, апгрейд).
- **Районы (ADR-019):** клетка сохраняет базовый `ZoneType`; район переопределяет ставку налога и рыночный множитель для своих клеток. Приоритет: override > база. Нет района, неизвестный район или `ZoneType.None` → старое поведение (ставка по зоне, множитель ×1, сбор 0). Распределение занятых — по принципу `ZonalJobs`: сумма равна ровно `employed`.
- **Рейтинг мэра (ADR-019):** бесконечный производный счётчик из вех и состояния города, без потолка и порога финиша; не автономная сохранённая ценность. Экранов победы/поражения нет (§19), `GoalSystem.Won/Lost` не воскресает. Последствия — через ленту и модификаторы существующих политик.
- **Решения игрока (ADR-020):** `DecisionController` применяет выбор на границе тика; `CityEventLog` получает две append-only записи (появление и применённый выбор) с разными ключами/аргументами, чтобы дедуп ADR-013 не склеил их. Отложенные решения не сериализуются, как пожары и агенты; после загрузки их нет. Coin-доктрина не меняется: `coin.wav` — только награда за ступень цели.
- **Сезоны и погода (ADR-021):** presentation-фильтр через `DayNightSample`/`DayNightPolicy` (те же 6 ключевых точек 0/6/9/12/18/22), детерминированный из игрового времени; системные часы и случайность запрещены. Окна загораются к вечеру через emissive-копии материалов; деньги, тики и сейв не меняются, новых полей в `CitySnapshot` нет.
- **Сейв v7 (ADR-022):** запись версии 7, чтение 1–7, версия > 7 — ошибка валидации. Опциональные поля (дороги, долг/процент, множитель, ставки районов, рейтинг, счётчик вех v2) с fallback на v6; некорректные значения получают дефолты без исключений и без перепроигрыша начислений. Экспорт/импорт идут по тем же правилам. `GameSettings` — профиль игрока, не состояние партии.
- **Тесты:** `X` EditMode-тестов в `X` файлах и `X` PlayMode-тестов; итоговые числа и `bundleVersion` финализирует оркестратор на гейте #171.
